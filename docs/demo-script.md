# A 100-second walkthrough

Read this conversationally. Pause between paragraphs; the product footage can cover the middle section. The demo uses a recorded Dream Labs run.

Robot demos look great. Then you ask, “Did it actually finish the task?” And someone has to watch the whole thing again.

I’m Kaushik. I built Reality Check to do that first review.

Here’s a real recorded run from Dream Labs. The task is simple: fold the dress.

As the video plays, Reality Check tracks what the robot is doing. One agent watches for progress. A second checks those observations against the footage. They communicate through Agent Relay.

And here’s the part I care about: you can check the answer. Open the evidence, click a timestamp, and see what the judgment is based on.

In this run, the dress ends up folded. The edges aren’t perfect, but that wasn’t the task. Reality Check looks for practical completion, and flags uncertainty when the footage isn’t clear enough.

Terse keeps the task, evidence, and agent handoffs in durable state. I can refresh the page, and the review is still here.

Today, Reality Check works with public robot videos and browser recordings. We’re starting with engineers testing robot policies, who need to understand what went wrong across their runs.

The next step is bringing this into their testing workflow, so they spend less time watching footage and more time improving robots.

That’s Reality Check. Every robot run should come with evidence.


## Recording notes

Record horizontally at 1080p or better, with the camera at eye level. If you stumble, pause and repeat the sentence without stopping the recording. Leave three seconds of quiet at either end.

Keep the source label visible in the app footage. If you cut waiting time, mark the transition as “Final review” so the edit does not imply an instant result.
